# workbuddy-token-meter v0.2.0 需求规格

- **版本**：v0.2.0
- **状态**：已冻结（Freeze）
- **日期**：2026-09-02
- **角色**：高级需求分析师裁定
- **适用范围**：Windows 桌面（Tauri widget + Python proxy）

## 1. 背景与目标

v0.1.0 已发布（悬浮窗 + 本地代理 + trace 旁路记账）。v0.2.0 的目标是让**没有配置过 WorkBuddy 自定义模型的新用户**也能开箱即用地看到自己的 token 用量，并让"是否走代理"的配置对用户可见、可管理、可逆。

核心诉求：扫描能力与代理配置解耦；key 统一单文件管理（方便安全与发布）；配置可演进、可回退；扫描结果持久化（启动秒级、不依赖原始 trace 留存）。

## 2. 用户旅程

**新用户（未配置自定义模型）**
1. 安装 exe → 打开 widget → 空态引导"扫描本地文件加载内置模型用量"
2. 点击扫描（或首次启动自动扫描）→ 进度反馈 → 内置模型用量加载（不依赖代理）
3. （可选）设置 → 一键导入 WorkBuddy 自定义模型 → 逐模型检查路由（直连/走代理）
4. 填 key（或导入）→ 点击"启动代理"→ 状态变绿，转发启用
5. 正常使用：走代理模型由代理实时记账，其他由 trace 增量扫描记账，同源展示

**已有用户（混合状态：部分模型直连、部分走代理）**
- 打开即见数据（缓存增量 + 代理记账合并）
- 在模型管理中随时切换任意模型的直连/代理路由，可逆

## 3. 关键决策裁定

| 决策点 | 裁定 | 理由 |
|---|---|---|
| 扫描与代理的解耦方式 | **proxy 常驻 + 双模式（service/full）**，不做 widget 内建扫描 | 扫描逻辑已在 Python 踩坑调稳，单一实现避免双份维护；service 模式零配置可用，full 模式启用转发 |
| 台账回退范围 | **仅还原 config.json**；models.json 路由改动走"恢复直连"按模型单独处理 | models.json 是 WorkBuddy 活配置，跨界回退会造成界面与 WorkBuddy 状态错乱 |
| 导入后 activeKey | **取第一个导入的 key**，界面可手动切换 | 规则简单可预期 |
| key 存储 | **明文唯一真源 = %APPDATA% 的 config.json**；台账/缓存/日志只存引用 id | 安全基线 + git 上传只排除一个敏感文件 |
| 路由开关默认态 | **保持导入时现状不动**，仅用户主动拨动才改 | 避免一键导入悄悄改动用户 WorkBuddy 配置 |

## 4. 功能点清单

### P0 核心闭环

1. **proxy 双模式（service / full）**
   - service 模式：扫描、统计接口可用；转发接口返回"代理未启用"提示
   - full 模式：配置 key 后一键切换，转发启用
   - 状态区常驻：运行模式、端口、本次会话转发请求数

2. **错误引导闭环**
   - 未配 key 点启动 → 引导去配置页
   - 端口被占用 → 明确报错
   - 停止转发 → 提示"WorkBuddy 里指向 127.0.0.1:8787 的模型当前不可用"

3. **扫描缓存**
   - 初次全量解析 trace，仅提取统计字段（ts / model / powered by / prompt/completion/cached/reasoning tokens / duration / status / 来源文件 + 会话内唯一标识）
   - 写入按天分片的自有缓存（`trace-cache/YYYY-MM-DD.jsonl`），不含请求体、不含 key
   - 后续扫描 stat 比对增量解析，upsert 进缓存（去重键 = 来源文件 + 唯一标识，容忍同一 trace 被追加重写）
   - 聚合只读缓存；提供"重新全量扫描"重建入口

4. **扫描反馈**
   - 进度：已扫文件数
   - 总结：N 会话 / M 记录 / X 模型
   - 首次启动自动扫描 + 空态引导（"点击扫描加载内置模型用量"）

5. **配置台账**（`config-ledger.json`，%APPDATA%，不入库）
   - 版本链：每次变更 = 完整 config 快照 + 变更元信息（时间 / 操作类型 / 来源）
   - 任意回退（范围：仅 config.json）
   - 模型登记表：模型名、渠道、原始直连 url（导入快照，永不覆盖）、当前 url、路由状态、key 引用 id
   - 变更日志

6. **一键导入 WorkBuddy 自定义模型**
   - 逐模型识别现状：直连（api.b.ai 等）提取 key 归入对应渠道（按 url host）；指向 127.0.0.1:8787 的跳过
   - 多 key 合并为渠道 keys 列表（activeKey = 第一个导入的，可切换）
   - 导入自动生成台账版本
   - 未检测到自定义模型时显示明确状态而非报错

7. **模型路由开关**
   - 每个自定义模型一个开关：拨动 = 改 models.json 对应模型 url（改前当前值入台账）+ 提示重启 WorkBuddy 生效
   - 可无限次直连/代理互切（台账保原始 url）
   - 默认保持导入时现状

### P1 体验增强

8. 双通道数据同源展示（总量 / 按模型 / 按天 / 趋势，扫描缓存 + 代理记账合并）

10. 台账界面：版本历史列表 + 一键回退 + 模型路由总览

## 5. 非功能需求（安全基线）

- key 明文唯一真源 = %APPDATA% 的 config.json；台账/缓存/日志一律只存引用
- 缓存与台账不含请求体、不含 key，可安全留存在本机
- 卸载保留 %APPDATA% 数据（升级不丢账本）
- git 侧只提交 example 模板，.gitignore 覆盖全部敏感产物
- 扫描性能：二次启动秒级（缓存增量）；全量重建后台执行不阻塞界面

## 6. 明确排除项（防范围蔓延）

- 不做多用户 / 团队共享
- 不做云端同步
- 不做手机端
- 本期仅 Windows 桌面
